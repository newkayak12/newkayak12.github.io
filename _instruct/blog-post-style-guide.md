# 블로그 포스트 스타일 가이드

기존 mini-project 시리즈 분석 기반. AI 포스트 수정 방향 포함.

## 기존 포스트 패턴

### 구조 패턴

주제 → 선택지 나열 → 선택 이유 → 결과 소감

- "이런 고민을 했다"
- "이런 선택지들이 있었다 (1, 2, 3)"
- "나는 이렇게 선택했다"
- "결과적으로 느낀 점은..."

### 형식

- `##` 메인 섹션, `###` 소섹션
- 탭 들여쓰기 중첩 불릿
- `**굵은 글씨**` 로 핵심 강조
- 선택지는 번호 목록으로 나열 후 선택 이유 설명
- `>` blockquote: 보조 자료, 정의, 사이드 메모용
- 마지막 소감은 짧게

### 톤

- "이걸 선택했다" ❌
- "이런 고민 끝에 이걸 골랐다" ✅
- 고민 과정과 다른 선택지의 존재를 명시
- 결과에 대한 솔직한 소감 포함

## AI 포스트 수정 방향

### 현재 문제

현재 AI 포스트는 **"뭘 만들었다"** 위주.
기존 포스트들은 **"왜 그쪽으로 갔냐"** 위주.

### 수정 목표

각 전환점마다 "왜?" 를 드러내기.

**예시 — Orchestration 섹션**

현재:
```
- Main Claude가 직접 다 처리 ❌
- agent-orchestrator 중간 조율자에게 위임 → 도메인별 에이전트로 분배
```

수정 방향:
```
- 처음엔 단순히 에이전트를 나열하고 Claude가 직접 판단하게 했다
- 근데 컨텍스트가 커질수록 판단이 흐려졌다
- "조율자를 따로 두면 어떨까?" 라는 생각에서 출발
- 1안: Claude가 직접 전부 처리
- 2안: agent-orchestrator를 중간에 두고 위임
- 결국 2안: 관심사 분리가 명확해지고 토큰도 아꼈다
```

### 전환 포인트별 "고민"이 필요한 섹션

1. **Claude Code 전환** — 웹 UI를 버린 이유
2. **Super Claude 포기** — 컨텍스트 소모 외에 구체적인 불편함
3. **Orchestration 설계** — 왜 이 구조인가, 다른 안은 없었나
4. **로컬 → Remote MCP** — 전환 결정의 순간
5. **MCP 3개로 줄인 것** — 뭘 기준으로 걷어냈나
6. **Skills 선택** — MCP/Commands 대비 왜 Skills인가

## 예시 참고 (mini-project 04 스타일)

```markdown
- 주변에 조언을 구했을 때 아래와 같은 답변을 받았다.
    1. 구분하지 않고 사용한다.
    2. 구분하지 않고 사용하되 필요한 곳은 구분한다.
    3. 철저하게 구분하여 사용한다.
- 특히나 지배적인 의견은 "**1. 구분하지 않고 사용한다.**" 였다.
    - 경제적인 측면에서 효율적이다.
    - 보일러플레이트가 너무 많이 생긴다.
- 그러나 프로젝트를 진행하면서 "**3. 철저하게 구분하여 사용한다.**"는 방법으로 하기로 결정했다.
    1. 의도적으로 다르게 설계하고 둘 간의 차이점을 느끼기 위해서
    2. 확장할 수 있는 방향성이 얼마나 다른가 확인하기 위해서
- 결과적으로 느낀 것은 "**꽤 다른 것 같다.**" 였다.
```
